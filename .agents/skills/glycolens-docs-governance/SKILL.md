# GlycoLens Documentation Governance

1. Read `AGENTS.md` and reuse the mandatory planning README and Updated Project Summary if they were already read, remain unchanged, and their required sections remain in context.
2. Inspect the request and complete diff; identify changed decisions rather than matching filenames mechanically.
3. Use [references/planning-impact-map.md](references/planning-impact-map.md) before opening specialized documents. Open every affected document, but avoid a pack-wide reread for a clearly bounded change.
4. Update all affected files in the same work cycle. Update the root README when setup, status, or navigation changes.
5. Compare targeted headings, terminology, cross-links, and changed claims. Run a broader contradiction review for milestone closure or architecture, model/dataset, scientific-method, or safety-boundary changes.
6. Report every planning document reviewed, whether it changed, and the reason.

Do not rewrite scientific hypotheses, model choices, features, or safety boundaries merely to mention tooling. Preserve source-of-truth content that the implementation did not change.
